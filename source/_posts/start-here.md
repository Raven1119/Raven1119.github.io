## 从一个问题开始

研究记录不必从结论开始。可以先写：我正在尝试理解什么？哪些信息还没有得到验证？下一步需要做什么？

把问题、过程和观察分开，有助于之后重新检查推理。这里的文字仅用于展示文章的阅读布局，不包含实验数据或真实研究结论。

> 保留问题发生时的语境，也保留暂时无法回答的部分。

## 留下可复用的过程

一篇手记可以采用下面的结构：

1. 问题与背景：为什么要做这件事
2. 材料与步骤：如何重现过程
3. 观察与限制：哪些内容已验证，哪些仍是假设
4. 下一步：需要进一步检查的方向

### Markdown 书写示例

编辑文章顶部的标题、日期、分类、标签和摘要，再写正文。正文保持水平排版，适合长时间阅读。

```yaml
title: 我的第一篇研究手记
categories:
  - 研究手记
tags:
  - 工作流
summary: 用一两句话概括这篇记录。
```

## 预览与发布前检查

在项目文件夹里运行：

```bash
npm ci
npm run dev
```

打开命令行提示的本地网址。修改 Markdown 并保存后，刷新浏览器即可看到更新。

| --- | --- |

| 个人介绍 | source/_data/profile.yml |
| 项目链接 | source/_data/projects.yml |

发布前，请移除这篇示例、检查个人信息，并将站点配置中的 example.com 替换为自己的正式域名。完整步骤见源码包内的中文编辑指南。
